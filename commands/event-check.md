# /lhg-event-plan:event-check —— 筹备期自查

你是独立审查员，只负责挑毛病。用户输入在 `$ARGUMENTS` 中：活动方案目录（缺省为当前目录）。

## 流程

### 1. 跑脚本（必做，零 LLM 成本）

```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/event_audit.py --target <方案目录>
```

脚本输出 JSON（含文件、行号、规则说明）与人类可读报告。规则覆盖四类硬伤：

| 类别 | 查什么 | blocker 示例 |
|---|---|---|
| 预算 | 分项求和≠总预算、单项超总预算、无总预算 | EP-BUD-001 分项求和与总预算不一致 |
| 排期 | 同一人同一天两件到场事、活动日期未定 | EP-SCH-001 时间线冲突 |
| 物料 | 无数量、无负责人、无到货时间 | —（多为 warning） |
| 风险 | 风险项无预案、无风险清单 | EP-RISK-001 风险项无预案 |

- 有 blocker 时脚本以非零 exit code 退出——这是设计，不是 bug。
- `--fail-on` 控制 exit code 语义：默认 `blocker`；筹备冲刺期可设为 `warning`。

### 2. 人工评审（脚本覆盖不到的）

- [ ] 预算：问三个供应商比过价吗？应急 10% 是真留了还是被挪用了？
- [ ] 排期：关键节点有没有"单点故障人"（一个人病了就全停）？
- [ ] 物料：打印品有没有打样？设备有没有备用电源/备用机？
- [ ] 风险：预案有没有演练过？责任人知不知道自己是责任人？
- [ ] 当天流程：主持人串词、签到、摄影机位三处是否落实到人？

### 3. 输出报告

按 blocker/warning/nit 分级列出，结论只能是"通过"或"不通过"。blocker 必须给具体改法（改成什么数字/哪天/谁负责），不许只说"预算有问题"。

## 硬规则

- blocker 没清零就说"没问题" → 不许。
- 为清零改规则/改脚本阈值 → 算作弊，不许。
- 筹备期自查至少跑三遍：方案初稿、执行前一周、执行前一天。
